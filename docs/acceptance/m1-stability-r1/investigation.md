# M1.1 调查记录（随实验结果补全）

## 旧记录复核

原始记录逐份 SHA、构建、GLB、条件及计算方式见 `original-record-index.json`。原始 M1 的十次尝试中九次完整，不删除失败或不完整尝试。

- 旧脚本在每个负载之前 `page.goto`。第三轮不是同一文档连续运行到第三轮；浏览器 TaskSpace 复用。
- 旧样本的页面运行时长未采集，不能拿首次渲染耗时代替页面年龄。
- 各份记录可检查 CSS 1920×1080、原生 DPR2、Three DPR1、1218×427 CSS / buffer。历史标签页清单、后台实际渲染负载、OS 遮挡和 CPU/GPU 电源状态未获取。
- 旧 FPS 为原始 rAF 间隔数 / 间隔总时长，P95 为排序后 floor(N×.95) 项；不是显示器实际呈现 FPS。旧 renderer.render 为 CPU 提交调用，不等同于 GPU 时长。
- 不事后将差成绩判无效。新复放是单独证据，不替代旧记录。

## 假设排序与短对照

1. 浏览器测试隔离 / 宿主调度干扰。当前发现四个同项目页均报告 visible + focus；清除每 target 的 focus emulation 后复测，短样本约59.56 FPS；重新打开其他页 focus emulation 短样本59.45 FPS。因此单凭四页存在不足以确认根因。先前同镜头短样本16.13 FPS仍保留；没有同步 CPU 轨迹，不能倒推原因。
2. 相机截止时间与页面隐藏竞态。代码在动画完成后可先成功、后处理迟到的超时回调。新增控制器回归测试在旧实现中语义失败（`deadline-semantic-before.log`），修复后通过。此项是已确认的交互缺陷，不是已确认的3.58 FPS根因。
3. 生命周期 / 数据 / 图表累积。检查并用资源计数及连续运行验证。旧诊断数据已暂停仍慢，因此快照刷新不是历史退化必要条件。
4. 原生 WebGL 提交或宿主等待。旧 CPU 轨迹的 TaskDuration 与 ThreadTime 差异支持等待/调度方向，但不是 GPU 测量，不足以区分驱动、宿主或外部争用。

## 已实施的局部修改

- 相机在更新前和渲染回执前检查单调时钟截止时间、可见性与取消；保留实际到位、选中、render 确认。PAGE_HIDDEN 是取消终态。
- Three 循环用单一生命周期所有者；隐藏停止、可见恢复，重复恢复不创建第二个循环；隐藏镜头取消不重放。
- 模拟刷新 interval 在隐藏时释放，恢复重置时钟并只开一个；不补跑隐藏时段。
- 图表相同尺寸不 resize，初始化仅一次 setOption；隐藏停止数据提交，恢复使用最新统一快照。没有重建图表、替换图表库或修改数据口径。
- 取消按钮保持固定位置，空闲时禁用；减少900ms动作期间寻找/布局变动的输入风险，没有延长镜头时长。
- QA 诊断默认关闭；每秒有界汇总，仅计应用拥有的资源，未知内部计数明确为 null。Three 资源计数不叫显存字节数。
- 新采样分别保存 rAF 回调时间、原始间隔、逻辑提交数和采样墙钟时长。Long Task 与 >50/>100ms间隔分别统计。

## 新复放条件

`baseline-replay` 在旧固定生产构建上复放原九次顺序，每负载重新导航，同一浏览器。保持布局/GLB/DPR、镜头和相同数据/面板负载。新增页面年龄与标签页清单，并清除每 target 的测试焦点仿真。该复放属于排查：期间有本项目源码编辑、Node 单元测试和类型检查，不能当最终验收成绩；没有并行截图/录屏/Profiler/其他浏览器性能测试。最终固定构建测试将独立串行执行。

初次 Node strip-types 导入控制器失败是测试接缝遇到参数属性语法；随后使用本机现有 transform-types 选项取得真正的语义失败。最终控制器使用显式字段，项目原 test 命令即可运行，不改系统或依赖。

## 诊断第一次收尾缺陷（保留原记录）

`diagnostics/PROFILER_ON.json` 收尾时 `result.done=false`。原脚本固定等23秒，慢动作尚未结束就进入下一条件，并把后续异步回执写入复用的全局对象。`FULL_AFTER_PROFILE` 的 measurement.measured_at 在该条件开始后约51ms即结束，而结果收集在23秒后，明确表明条件归属混淆。这不是因成绩差而排除；第一次 FULL 的已完成33.35FPS / P95 84.8ms短样本仍保留为前台差样本，全部原始文件和脚本均保留。

`diagnostics-r2/` 改为每个实验独立结果对象、观察完成状态后才进入下一条件，最长120秒后停止而不重叠。CPU采样仅在明确标记的条件启用，其他条件无CPU Profiler。将另行成对检查轻量诊断与CDP metrics本身的开销；正式性能全部关闭这些诊断。

## 最终观测

- 正式固定构建65ab…九份均满足本次记录的前台文档、固定资产/DPR/尺寸、时长条件；全部未达目标，第三轮C平均3.14FPS、P95 2101.9ms。不将OS遮挡未知当作删除差样本理由。
- 同构建独立新开文档持续1117.91秒，15完整窗口均无document隐藏；后段13–15在不重载/重建renderer、不改代码/参数的情况下恢复约60FPS。因此同页暂时恢复仍只是线索。
- 正常50Hz函数轨迹profile阶段59.13FPS，render CPU平均约0.86ms/最大2ms；退化后的200Hz轨迹render CPU平均约36.45ms/最大256.7ms。采样开销不同，不能将此差称GPU时间。低频正常轨迹没有代替任何失败样本。
- 独立静态合批把50draw降到20、几何/材质/三角面与图像基本一致，但正反序列不能分离宿主时变因素。实验撤回，原型/八份结果/像素比较保留，生产源码逐字节回到冻结65ab…。
- 原生取消正常+受控压力、真实hidden/visible正常+受控压力均通过；极端3.14FPS时原生取消未同步补测。
- 后端/数据库/模型资产/新工具均未增加；保护文件233项、最终源码34项、dist摘要、package/lock均校验通过。重启普通生产入口及两工具通过。

仍未确认根因：底层WebGL提交等待、Electron/宿主调度、GPU争用或其他外部/产品交互因素。准确GPU时间/VRAM、OS遮挡/宿主负载/电源频率、测量全程context-lost事件未获取。停止本轮，不进入M2。
